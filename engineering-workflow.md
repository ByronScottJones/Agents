# Engineering Workflow

Load this file for team development practices and delivery expectations.

## Work Items

- Define the expected behavior, constraints, validation, and completion criteria before implementation.
- Keep changes focused and reviewable; separate unrelated refactors.
- Preserve public contracts unless a breaking change is explicitly planned.
- Track technical debt with an owner, impact, and follow-up path.

## Review

- Review correctness, security, operability, tests, documentation, and migration impact.
- Prefer executable validation over inspection alone.
- Record important design decisions and operational assumptions.
- Keep ownership and escalation paths visible.
